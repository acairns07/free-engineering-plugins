# PRD quality questions

- Problem: which observed user difficulty changes, and what evidence supports it?
- Outcome: can the measure distinguish delivered output from improved user outcomes?
- Scope: does the first release complete one journey, including its failure states?
- Requirement: can an engineer and tester independently reach the same interpretation?
- Access: which actor may read/change which object? How are cross-account requests rejected?
- Data: what is essential, where does it live, how long does it remain, and how is it deleted?
- Integration: who owns the contract, quotas, credentials and failure recovery?
- Accessibility: keyboard, focus, labels, error association and contrast have testable criteria.
- Operations: what detects failure, who responds, and what supports rollback?
- Readiness: unresolved decisions have an owner, deadline and effect of delay.

Do not convert unknowns into requirements without marking the assumption. A target without a baseline can still be proposed, but must not be described as validated.
